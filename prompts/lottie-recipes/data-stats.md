# 레시피: 데이터 · 숫자 · 차트

KPI, 큰 숫자 리빌, 진행·목표 카드, 간단한 차트, 결과 행, 앱 안 통계 위젯. 공통 규칙은 `prompts/lottie.md`.

## 기본

- 만들기 전에 데이터 원형을 하나 고른다. 숫자를 위해 레이아웃을 즉흥으로 만들지 않는다.
- 제목이 통찰을 말하고, 차트·숫자가 확인한다.
- 중립 위에 의미 있는 포인트 하나, 또는 한 색상의 두 명도.
- 테두리 없는 숫자를 여백에 띄우거나, 균일한 자기완결 카드. 묶음을 감싸는 바깥 카드·테두리 금지. 표면 톤 하나. 열 구분이 꼭 필요하면 같은 폭 열 사이에 한 색 헤어라인 하나(여백이 먼저).
- 숫자는 카운트업(구운 키프레임). 정적 숫자를 페이드로 띄우지 않는다.
- 앱 위젯이면 투명, 화면 전체 장면이면 `bg` 슬롯.

## 원형 고르기

| 원형 | 언제 |
|---|---|
| 히어로 숫자 | 감정적인 지표 하나, 숫자와 라벨의 극단적 크기 대비 |
| KPI 그리드·세 개 카드 | 나란한 증거 여러 개, 한 템플릿 반복 |
| 결과 행 | 헤어라인 라벨/값 행 |
| 비교 차트 | 포인트 대 중립 막대·선·띠 하나 |
| 진행·목표 카드 | 실제 대 목표, 목표선, 링 |
| 대시보드 지표 | 히어로 지표 하나 + 차트 하나 + 가벼운 상태 |

## 타이밍과 이징 (60fps)

- 작은 숫자 카드: 60~120f. 여러 카드·차트: 120~210f.
- 금융·연구·기업 데이터는 차분한 ease-out(`.00,.65,.51,.99`), 넘침 없음. 작은 팝은 배지·소비자용·SNS 패널에만.
- 보조 글자는 숫자·도형이 멈춘 뒤.

## 만들기

- 카운터는 키프레임으로 굽는다(표현식 BLOCK). 자릿수마다 `h:1` 계단: 숫자 글리프 0~9를 `lottie.mjs text`로 만들어 자리마다 불투명도 계단으로 바꾸거나, 정해진 중간 값 몇 개(예: 0 → 12 → 38 → 64 → 72)만 글자 레이어를 교체. 카운트 곡선은 거의 선형 + ease-out 착지.
- 자리마다 같은 폭 칸에 가운데 정렬해 자릿수가 흔들리지 않게. 카운트 동안 값 전체가 가운데에 머물게.
- 숫자를 도형과 맞춘다: 막대가 높이에 닿을 때 값이 멈추고, 선이 점에 닿을 때 라벨이 멈춘다.
- 막대·선·축·연결선·구분선은 트림 패스. 둥근 막대·카드는 스케일하지 말고 `rc`의 `s` 키프레임(모서리가 늘어나지 않게). 손으로 만든 마스크는 WARN.
- 값에 직접 라벨. 짧은 장면에서 축·범례 해석을 요구하지 않는다.
- 라벨과 값이 한 행이면 대문자 높이 중심을 맞춘다(같은 기준선이면 작은 쪽이 가라앉는다).
- 슬롯: 포인트 컬러, 배경, 필요하면 차트 색. 숫자·문구는 아웃라인이라 슬롯이 아니다.
- 제3자 로고·인증 마크·얼굴 사진은 디자이너가 준 것만.

## 흔한 실패

- 제목이 주제만 말하고 통찰을 말하지 않는다.
- 숫자가 카운트 없이 페이드로 나온다. 자릿수가 흔들린다.
- 무지개 색이 장식이 된다. 한 비트에 지표가 너무 많다.
- 진지한 데이터에 바운스.
- 불필요한 바깥 카드·테두리, 굵기·색이 다른 구분선, 겹친 두 톤 표면.
- 둥근 막대가 스케일로 늘어났다.

## 통과 조건

- 원형이 지표의 일에 맞고, 제목이 요점을 말하고 데이터가 확인한다.
- 숫자에 직접 라벨, 카운트업, 읽힘.
- 도형과 숫자 라벨이 함께 멈춘다.
- 크롬을 다 지워도 위계가 읽힌다.
- 마지막 프레임이 깨끗한 정지 데이터 화면이다.
