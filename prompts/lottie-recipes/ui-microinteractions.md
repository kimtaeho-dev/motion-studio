# 레시피: UI 마이크로 인터랙션

버튼 상태, 토글, 탭 피드백, 알림, 진행 상태, 온보딩 힌트, 폼 성공, 작은 제품 UI 움직임. 공통 규칙은 `prompts/lottie.md`.

## 기본

- 짧고 즉각적. 사용자 행동 직후에 느리게 느껴지면 실패다.
- 디자이너의 UI 스타일(모서리, 색, 굵기)을 그대로 따른다.
- 거리는 작게, 상태 변화는 분명하게. **상태 변화가 클라이맥스** — 그 전은 준비, 그 후는 확인.
- 믿음은 촘촘한 UI 디테일이 아니라 일관된 상태에서 나온다.
- 투명 배경. 컴포넌트 카드 전체를 보여줄 때만 칠한 배경.
- UI에서 넘침·바운스 금지(CLAUDE.md).

## 프리셋

| 이름 | 무엇 |
|---|---|
| `soft-confirm` | 성공 체크·상태 아이콘이 그려지고 착지 |
| `toggle-shift` | 손잡이가 미끄러지며 색·불투명도 상태가 바뀜 |
| `button-press` | 눌림 스케일(97~98%)·밝기 → 빠른 복귀 |
| `notification-pop` | 작은 카드·아이콘 등장, 멈춤, 퇴장 |
| `progress-fill` | 정해진 진행 바·링 채우기, 읽히는 이징 |
| `empty-nudge` | 작은 일러스트·아이콘이 행동을 조용히 권함 |

## 타이밍과 이징 (60fps)

- 눌림·호버 피드백: 8~18f, `.20,.75,.34,.94`.
- 토글·진행·상태 전환: 18~45f, 이동 `.65,0,.35,1` 또는 착지 `.00,.65,.51,.99`.
- 알림 등장·퇴장: 30~75f(퇴장은 `1.00,.02,.54,.42`, 등장보다 짧게).
- 손잡이·채움·색·라벨처럼 한 값이 여러 속성을 움직이면 **잠금**(같은 시작·끝 프레임, 같은 곡선).

## 만들기

- 둥근 버튼·바·트랙은 `rc`(`r` 고정)로. 늘리는 리빌은 스케일이 아니라 `rc`의 `s`(크기) 키프레임 — 스케일하면 모서리가 찌그러진다.
- 관련 상태들의 타이밍을 맞춘다(켜짐·꺼짐이 같은 길이). 되돌릴 수 있는 전환이면 앞뒤 대칭으로.
- 개발자가 구간을 나눠 재생할 수 있게(예: 켜짐 0~30f, 꺼짐 30~60f) 상태마다 멈춘 포즈를 프레임 경계에 둔다. 구간을 `brief.md`의 gotchas나 전달 메모에 적는다.
- 슬롯: 포인트 컬러, 트랙·바 색. 라벨 문구는 아웃라인이라 슬롯이 아니다.
- 브랜드 인트로 같은 큰 움직임을 기능 UI에 넣지 않는다.

## 흔한 실패

- 행동 뒤 느리게 느껴진다.
- 컴포넌트 크기에 비해 움직임이 크다.
- 주변 UI 없이는 상태 변화가 안 읽힌다.
- 활성 상태, 라벨, 도형이 서로 다른 말을 한다.
- 마지막 상태가 컴포넌트 도형에 맞지 않는다.

## 통과 조건

- 상태 변화가 즉시 전달된다.
- 주변 맥락 없이도 상태가 일관되고 읽힌다.
- 튐·잘림·어색한 넘침이 없다.
- 작게 봐도 읽힌다.
