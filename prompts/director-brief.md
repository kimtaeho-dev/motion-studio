# 디렉터 브리프 — 긴 작업(30초 이상, 여러 세션)용

긴 필름이 나온 프롬프트들은 9,500~19,000자였다. 영상을 묘사하지 않고 "크루를 고용"한다. 뼈대는 이렇다.

```md
너는 코드로 만드는 [길이] 필름의 감독, 애니메이터, 사운드 디자이너, 렌더 엔지니어다.
여러 세션에 걸친 프로덕션으로 다룬다. 최종 렌더를 서두르지 않는다.

## 한 줄 요약
[로그라인. 끝났을 때 보는 사람이 느껴야 할 것.]

## 레퍼런스와 입력
- films/<이름>/refs/ : [영상 / 프레임 / 이미지 라이브러리]. 문법만 가져오고 내용은 가져오지 않는다.
- films/<이름>/audio/track.wav : 그대로 쓴다. BPM [  ] · 첫 다운비트 [  ]초.
- 쓸 수 있는 API는 .env에: [ELEVENLABS_API_KEY …]. 예산: [$X]. 아껴 쓴다.

## 룩
[3~5줄: 팔레트, 타입, 질감, 카메라 언어. 금지 룩.]

## 비트 시트
0:00-0:02  훅: [가장 강한 이미지 하나]
0:02-0:10  [1막]
...        3~5초마다 새로운 시각적 보상
[끝]       마지막 프레임이 첫 프레임으로 이어진다 (루프)

## 화면 텍스트
가사/자막이 언제 크게, 언제 자막처럼 앉는지. 구도는 텍스트 자리를 비워둔다.

## 작업 순서 (게이트)
1. style_guide.md, shotlist.md (숏마다: 프레임, 카메라, 텍스트, 효과음). 숏리스트를 보여준다.
2. 숏마다 스틸 → 컨택트 시트 → 크리틱.
3. 960x540 애니매틱 (--draft). 폴리시 전에 페이싱부터 고친다.
4. 전체 애니메이션 → 폴리시 → 사운드 → 최종 렌더.
5. 챕터별로 서브에이전트에게 나눈다. 먼저 docs/ANIMATION_GUIDE.md를 써서 모두 같은 스타일로 코딩하게 한다.

## 크리틱 루프 (숏마다 최소 3라운드)
prompts/critique-pass.md 기준. review_log.md에 점수와 큰 문제 3개를 남긴다. 모두 8점 이상까지.

## 결과물
final.mp4 · loop_check.mp4 · poster.png · contact.png · README
```

API 키는 프롬프트에 붙여넣지 않는다. `.env`에 두고 "ELEVENLABS_API_KEY는 .env에 있음"이라고만 쓴다.
