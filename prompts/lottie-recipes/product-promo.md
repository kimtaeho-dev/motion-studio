# 레시피: 기능 소개 · 런칭 카드 · 프로모

앱·웹에 들어갈 기능 소개, 런칭 카드, 업데이트 소식, 온보딩 히어로, 짧은 프로모 Lottie. 편집·SNS용 영상이면 영상 필름이 맞다(`prompts/lottie.md` 언제 Lottie인가). 공통 규칙은 `prompts/lottie.md`.

## 기본

- 제품·기능이 주인공. 문구는 짧게, 메시지 하나를 분명히.
- 주장 하나 + 제품 증거 하나. 스크린샷 콜라주 금지.
- 제품 신호가 보이지 않는 흔한 런칭 카드 레이아웃 금지.
- 오브젝트 예산: 주인공 → 보조 디테일 → 포인트 체계.
- 화면 전체 구성이면 `bg` 슬롯. 투명 에셋 요청이면 투명.
- 장면이 여럿이면 숏리스트 게이트(`chapterization-transition-grammar.md`).

## 만들기 전에 정한다

- 주인공: 제품 화면, 기능 표면, 로고, 사물, 메시지 하나.
- 제품 신호: UI 조각, 썸네일, 기능 콜아웃, 데이터 칩, 브랜드 도형, 알아볼 수 있는 흐름 한 단계.
- 증거: 화면 디테일, 믿을 만한 UI 상태, 지표, 결과.
- 마지막 포스터 프레임: 제목 위치, 제품 크기, 메시지 초점.
- 믿음은 디테일 양이 아니라 일관된 제품 상태·흐름·문구·위계에서.

## 프리셋

| 이름 | 무엇 |
|---|---|
| `hero-card-reveal` | 제품 카드·화면 등장, 제목이 따라옴 |
| `feature-spotlight` | 기능 영역 하나가 강조 + 라벨 |
| `proof-object` | 주장 등장 → 제품 증거 하나가 움직임 → 보조 문구 |
| `update-stack` | 기능 칩·카드 여러 개가 엇갈려 자리 잡음 |
| `social-loop` | 첫·마지막 프레임이 분명한 짧은 루프 |
| `launch-burst` | 제목·제품 리빌 + 절제된 축하 액센트 |

## 타이밍과 이징 (60fps)

- 단일 소식: 90~150f. 여러 비트: 150~240f.
- 주인공 착지 `.00,.65,.51,.99`, 보조 문구·칩은 4~8f 엇갈림 `.20,.75,.34,.94`.
- 루프는 제품 맥락에 맞게 은은하게.

## 만들기

- 레이어 구성: 주인공 · 문구 묶음 · 포인트 · (배경). 묶음은 널 부모로 움직인다.
- 제품 화면이 비트맵이면 디자이너가 준 이미지를 `lottie.json` 옆 파일로(`assets[].p`). 용량 150KB 예산에 들어가는지 `check`로 확인. 가능하면 UI를 벡터 도형으로.
- 팬·줌이 필요하면 `camera-scene-motion.md` 보조. 광택·스윕은 `visual-effects.md` 보조.
- 그라데이션이나 대기 루프는 하나까지(효과가 주인공일 때만 더).
- 빈 카드 대신 화면 디테일, 작은 UI 행, 썸네일, 지표 칩.
- 문구는 `lottie.mjs text`로. 슬롯은 포인트·배경 색.

## 흔한 실패

- 디자이너의 제품이 아닌 흔한 광고처럼 보인다.
- 주장에 보이는 증거가 없다. 문구가 너무 많고 빠르다.
- 효과가 제품과 경쟁한다. 제품 표면이 너무 작거나 비어 있다.
- 빈 카드·장식 액센트로 템플릿 같다.

## 통과 조건

- 제품·기능이 틀림없이 주인공이다.
- 주장, 증거, 마지막 메시지가 일치한다.
- 문구가 붐비지 않고 읽힌다.
- 마지막 프레임이 정지 그래픽으로도 성립한다.
