# 레퍼런스 — 스타일을 "설명"하지 말고 "이름 붙이고 보여준다"

레퍼런스가 없으면 Opus는 기본값으로 돌아간다: 가운데 텍스트, 그라데이션 배경, 전부 페이드인.
스타일을 묘사하는 것보다 이름을 붙이는 게 낫고, 레퍼런스 영상이나 프레임 한 장이 페이싱·타입·전환을 가장 잘 전달한다.

## 세 가지 방법

- **프레임 1장**: 좋아하는 영상의 한 프레임을 `refs/`에 넣고, 가져올 것(팔레트, 타입, 그레인)과 가져오지 않을 것(피사체)을 말한다.
- **영상**: `refs/ref.mp4`를 넣는다. ffmpeg로 프레임을 뽑아 숏 단위 페이싱을 먼저 설명하게 한다.
- **라이브러리**: 내 이미지나 지난 작업 폴더. 남이 복사할 수 없는 레퍼런스다. 먼저 `style_guide.md`를 쓰게 한다.

참고할 곳: Dribbble 모션, 런칭 영상 모음, 경쟁사 런칭 필름, 우리 팀의 지난 작업.

## 프롬프트

```
레퍼런스: films/<이름>/refs/ (ref.mp4, frames/*.png)
1. ffmpeg로 0.5초마다 프레임을 뽑아서 본다.
   ffmpeg -i refs/ref.mp4 -vf "fps=2,scale=480:-1" refs/frames/%03d.png
2. films/<이름>/style_guide.md를 쓴다: 팔레트(hex), 타입(서체, 굵기, 자간), 숏 길이,
   전환 종류, 카메라 무브, 질감/그레인, 텍스트가 들어오고 나가는 방식.
3. 그 스타일로 films/<이름>/shotlist.md를 쓴다.
   레퍼런스의 "문법"만 가져오고, 내용·로고·캐릭터는 절대 가져오지 않는다.
4. 두 파일을 보여주고, 내 OK 전에는 코드를 쓰지 않는다.
```

레퍼런스를 줄 때는 기법을 정하지 않는다. 룩과 제약만 정하고 라이브러리 선택은 모델에게 맡긴다.
