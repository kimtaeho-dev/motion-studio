# Lottie 필름 — 규칙과 작업 순서

> lottie-studio의 text-to-lottie 스킬(diffusionstudio/lottie, MIT — tools/lottie/LICENSE-diffusionstudio-lottie)을 이 레포에 맞게 옮긴 것.

Lottie 필름을 만들거나 고치기 전에 이 문서를 읽는다. 레시피는 맨 아래 [레시피 라우팅](#레시피-라우팅) 표에서 맞는 것만 연다(전부 열지 않는다).
`lib/*.js`·`tools/lottie/*` 소스는 통째로 읽지 않는다(여기 없는 걸 찾을 때만 `grep`).
CLAUDE.md의 하우스 룰(작업 필름 폴더만 고침, 디자이너가 바꾼 값을 말없이 되돌리지 않음, 폰트, 소리 없음, 룩 금지 목록)은 그대로 적용된다. 영상 필름의 코드 규칙(`Stage.film`, `draw`, `M.spring`)은 Lottie 필름에는 해당하지 않는다.

## 언제 Lottie인가

| 결과물 | 필름 종류 |
|---|---|
| 앱·웹 화면에 들어갈 것(로더, 성공·실패 상태, 아이콘, 버튼 피드백, 로고 리빌, 온보딩 일러스트) — 개발자가 JSON으로 받아 플레이어로 재생 | **Lottie 필름** |
| 편집·SNS·발표에 쓸 영상(mp4·ProRes), 3D, 물리, 카메라가 큰 화면 연출 | 영상 필름(`prompts/api.md`, `prompts/3d.md`) |
| 영상 필름 안에 이미 만든 Lottie를 부품으로 넣기 | 영상 필름에서 `await Stage.lottie('../<이름>/lottie.json')` → `.draw(g, x, y, { t, width, slots })` (`lib/stage-lottie.js` 맨 위 주석) |

Lottie는 벡터 키프레임만 담는다. 블러·글로우 같은 이펙트, 3D, 물리, 표현식은 쓸 수 없다(아래 [렌더러 제약](#렌더러-제약)). 브리프가 이런 것에 기대면 영상 필름을 권한다.

## 폴더와 파일

```
films/<이름>/
  lottie.json   결과물. 에이전트가 손으로 쓴다
  film.json     lottie.json에서 sync로 맞춘다(kind·dur·fps·formats·params). params의 label만 손으로 고친다
  index.html    고정 셸 — Stage.lottieFilm() 한 줄. 고치지 않는다
  brief.md      브리프 (Lottie용 템플릿)
  refs/         디자이너 첨부(그대로 쓰기 SVG, 레퍼런스)
  state.json    진행 단계 — tools/state.mjs로만 기록
```

- 만들기: 앱의 새 필름 창에서 "앱·웹에 넣을 것", 또는 `node tools/new.mjs <이름> --lottie --size 512x512 --dur 2`.
- 미리보기와 렌더는 **Skottie**(CanvasKit 0.41.1, CPU 래스터)다. 개발자는 **lottie-web / iOS / Android 플레이어**로 재생한다. 그래서 Skottie에서 멀쩡한 것으로는 부족하고, 두 렌더러가 같게 그려야 전달할 수 있다(`--parity`).
- 이미지 에셋은 `lottie.json` 옆(또는 `assets[].u` 폴더)에 파일로 두고 `assets[].p`에 파일명만 적는다. base64 인라인(`e:1`)으로 쓰지 않는다 — 내보낼 때 `lottie.mjs export`가 넣어 준다.

## 작업 순서

단계마다 `node tools/state.mjs films/<이름> stage=<단계>`로 기록한다. Lottie에는 `draft` 단계가 없다.

1. **브리프** (`stage=brief`) — `brief.md`를 채운다. 결과가 눈에 띄게 달라지는 것만 묻는다: 투명/배경, 크기·길이·루프, 브랜드(포인트) 색, 문구, 개발자가 쓸 플레이어. 빈칸이 있으면 묻고 `waiting=answer`로 기록한 뒤 **턴을 끝낸다.** 답이 없어도 되는 것은 기본값으로 정한다(아래 표). 단, 새 필름 창에서 디자이너가 고른 크기·길이(`lottie.json`의 `w`·`h`·`op`)는 기본값이 아니다 — 다른 값을 권하려면 질문으로 묻고, 답 없이 바꾸지 않는다(CLAUDE.md).
2. **레퍼런스가 있으면** `refs/`에서 `style_guide.md`를 먼저 쓴다(`prompts/reference.md`). 문법만 가져온다.
3. **갈래**
   - **에셋 하나**(아이콘, 로더, 상태 피드백, 마이크로 인터랙션 하나, 로고 리빌 하나): 숏리스트 게이트 없이 바로 4로.
   - **장면·챕터가 여럿**: `shotlist.md`(비트 | 시각 | 상태 / 동작 | 커서 표)를 쓰고 `stage=shotlist waiting=approval`, 채팅에 표를 보여주고 **턴을 끝낸다.** 승인(앱 승인 버튼 또는 채팅의 분명한 OK) 전에는 `lottie.json`을 쓰지 않는다. 챕터 나누기는 `prompts/lottie-recipes/chapterization-transition-grammar.md`.
4. **만들기 + 스틸** (`stage=stills`) — `lottie.json`을 쓴다 → `node tools/lottie.mjs sync films/<이름>` → `film.json` params의 `label`을 한국어로 → `node tools/lottie.mjs check films/<이름>`(BLOCK 0) → `node tools/render.mjs films/<이름> --stills 0.2,0.5,1`(핵심 시각) 또는 `--stills beats`(컨택트 시트)를 **직접 열어서 본다.** 고칠 점은 모아서 한 번에 고치고, 바뀐 시각만 몇 장 다시 본다.
5. **크리틱** (라운드마다 `stage=critique round=<N>`) — 매 라운드: `lottie.mjs check`(BLOCK 0, WARN 확인) → `render.mjs --parity`(통과) → 스틸/컨택트 시트 → 움직임은 풀 렌더(`node tools/render.mjs films/<이름>`) 뒤 `node tools/critique.mjs films/<이름>`의 strip·seam·phone으로 본다 → `prompts/critique-pass.md` 기준 채점(아래 [검사와 완료 조건](#검사와-완료-조건)의 해석) → `review_log.md`에 `## 라운드 N`. 라운드 수는 `state.json`의 `quality`를 따른다(`fast` 1 · `standard` 3 · `launch` 모든 항목 8점 이상, 최소 3, 6을 넘기면 `waiting=answer`).
6. **전달** (`stage=deliver waiting=none`) — `node tools/lottie.mjs export films/<이름>` → `out/<이름>/lottie/<이름>.json`(이미지 포함) · `<이름>.lottie`. 포스터 프레임: `--stills <시각>` 결과(`out/<이름>/<WxH>/stills/`)를 `out/<이름>/<WxH>/poster.png`로 복사. 다음에 개선할 점 한 줄. 앱의 내보내기 창에도 "Lottie"(그리고 MP4/GIF/WebM 렌더)가 있다.

`lottie.json`을 고칠 때마다: 다시 읽고(앱이 film.json을 고쳤을 수 있다) → 고치고 → `sync` → label 확인 → `check`.

### 브리프 기본값 (묻지 않아도 되는 것)

| 항목 | 기본 |
|---|---|
| 크기 | 아이콘·로더·상태 `512x512` · 로고 원본 SVG viewBox 비율 · 히어로·온보딩 일러스트는 들어갈 자리 비율 |
| fps | 60 (`fr: 60`) |
| 길이 | 마이크로 인터랙션 0.2~0.5초 · 상태 피드백 0.5~1.25초 · 로더 1~2초 루프 · 로고 0.75~2초 · 여러 장면 2~4초 |
| 배경 | **투명**(로고·아이콘·로더·오버레이·SVG 파생). 화면 전체를 채우는 카드·일러스트일 때만 칠한 배경 |
| 루프 | 로더·앰비언트는 루프, 상태·로고는 한 번 재생 후 멈춤(마지막 포즈가 정지 화면이 된다) |

## 슬롯과 속성 패널

디자이너가 바꿀 값은 Lottie **슬롯**으로 뺀다. 코드에 박지 않는 것과 같은 원칙이다.

```json
"slots": { "accent": { "p": { "a": 0, "k": [0.1843, 0.4196, 1, 1] } } },
...
{ "ty": "fl", "c": { "a": 0, "k": [0.1843, 0.4196, 1, 1], "sid": "accent" }, "o": { "a": 0, "k": 100 }, "r": 1 }
```

- 최상위 `slots.<sid>.p` = `{ "a": 0, "k": 값 }`. 속성은 `"sid": "<sid>"`로 참조한다. 속성의 인라인 `k`도 슬롯 기본값과 같게 둔다(슬롯을 모르는 플레이어는 인라인 값을 쓴다).
- `sync`가 `film.json` `params`를 만든다. **키 = sid.** color·number 슬롯만 앱 속성 패널에 올라간다. vec2(위치·크기)와 키프레임이 있는(`a: 1`) 슬롯은 올라가지 않는다.
- `sync` 뒤 각 param의 `label`을 디자이너가 알아볼 한국어로 고친다("포인트 컬러", "체크 색", "배경"). label이 sid 그대로면 `check`가 BLOCK.
- `sync`는 label과 디자이너가 바꾼 값을 지킨다. 슬롯의 종류(color↔number)가 바뀌면 그 param만 `lottie.json` 값으로 다시 시작한다 — 종류를 바꿔야 하면 디자이너에게 먼저 말한다.
- 디자이너가 바꾼 값은 내보낼 때 슬롯에 구워진다. `lottie.json`의 슬롯 기본값을 디자이너 값으로 덮어쓰거나 되돌리지 않는다(CLAUDE.md).
- 무엇을 슬롯으로: 포인트 컬러, 잉크(글자·선) 색, 칠한 배경이면 `bg`, 필요하면 선 굵기. 전부 슬롯으로 만들지 않는다 — 디자이너가 실제로 바꿀 것만.
- 같은 sid를 여러 속성이 참조해도 된다(값 종류가 모두 맞아야 한다). 색 슬롯은 `[r, g, b, a]` 0~1.
- 문구는 슬롯이 아니다. 글자는 아웃라인이라(아래 [글자](#글자)) 문구를 바꾸려면 대화로 요청받아 `lottie.mjs text`로 다시 만든다.

## Lottie JSON 핵심

**최상위** — `v`(`"5.12.0"`), `nm`, `fr`, `ip`, `op`, `w`, `h`, `ddd: 0`, `assets`, `layers`(+ `slots`). 하나라도 없으면 BLOCK.
- `ip` 포함, **`op` 제외**: `fr 60, ip 0, op 120` → 프레임 0..119, 2초. 마지막 프레임은 `op - 1`.
- `nm`은 필름 제목. `w`·`h`는 `film.json` formats(`"WxH"`)로 간다.

**레이어** (`layers[0]`이 맨 위에 그려진다)

| `ty` | 종류 | 메모 |
|---|---|---|
| 4 | 셰이프 | 기본. `shapes` 배열 |
| 3 | 널 | 묶어 움직일 부모 |
| 0 | 프리컴프 | `refId` → `assets[].layers`, `w`·`h` |
| 2 | 이미지 | `refId` → `assets[]` 이미지 |
| 1 | 솔리드 | 배경은 셰이프 `rc` + `bg` 색 슬롯이 낫다 |
| 5 | 텍스트 | **BLOCK** — 쓰지 않는다 |

- 공통 필드: `ddd: 0`, `ind`(필름 안에서 유일), `ty`, `nm`(한국어 이름 — 보고서·디버깅용), `sr: 1`, `ip`, `op`, `st: 0`, `bm: 0`, `ks`.
- `ks`(변환): `o` 불투명도 0~100 · `r` 회전(도) · `p` 위치 `[x, y, 0]` · `a` 기준점 `[x, y, 0]` · `s` 스케일 `[100, 100, 100]`.
- 레이어는 `ip <= 프레임 < op` 동안 보인다. 장면마다 `ip`/`op`를 맞춘다(들어오기 전·나간 뒤에 투명도 0으로 남겨 두지 않는다).
- `parent: <ind>`로 변환을 물려받는다. 순환 금지. 여러 요소를 같이 움직이면 각자 키프레임을 찍지 말고 널(`ty:3`) 부모 하나를 움직인다.
- 매트·마스크·프리컴프·타임 리맵은 유효하지만 더 깨지기 쉽다. 단순한 셰이프·레이어 구조로 안 될 때만.

**셰이프 아이템** (그룹 `gr`의 `it` 배열 안)

| `ty` | 무엇 | 주요 필드 |
|---|---|---|
| `gr` | 그룹 | `it`, 마지막 항목은 반드시 `tr` |
| `sh` | 패스 | `ks.k = { c, v, i, o }` — `i`·`o`는 정점 기준 상대좌표 |
| `rc` | 사각형 | `p` 중심, `s` 크기, `r` 모서리 |
| `el` | 원 | `p`, `s` |
| `sr` | 별·다각형 | `sy`(1 별, 2 다각형), `pt`, `or`, `ir` … |
| `fl` | 칠 | `c` 색, `o`, `r`(1 nonzero · 2 evenodd) |
| `st` | 선 | `c`, `o`, `w`, `lc`(1 butt 2 round 3 square), `lj`(1 miter 2 round 3 bevel), `ml` |
| `gf` · `gs` | 그라데이션 칠·선 | `t`(1 선형 2 방사), `s`·`e`, `g: { p: 정지점 수, k }` |
| `tm` | 트림 패스 | `s`·`e` 0~100, `o` 각도, `m: 1` |
| `rp` | 리피터 | `c` 개수, `o`, `tr`(`so`/`eo` 포함) |
| `tr` | 그룹 변환 | `p a s r o sk sa` — 2D 값 |

- 칠·선은 같은 그룹 안에서 **자기보다 앞에 있는** 도형에 적용된다. 칠·선이 없는 도형은 안 그려진다.
- 그룹 안에서는 앞 항목이 위에 그려진다(역순 스택). 순서가 중요하면 스틸로 확인한다.

**키프레임**

```json
"p": { "a": 1, "k": [
  { "t": 0,  "s": [256, 300, 0], "o": { "x": [0.2], "y": [0.75] }, "i": { "x": [0.34], "y": [0.94] } },
  { "t": 18, "s": [256, 256, 0] }
] }
```

- 정적 `{ "a": 0, "k": 값 }` · 움직임 `{ "a": 1, "k": [키프레임] }`. `t` 오름차순. 프레임 단위(60fps면 30 = 0.5초).
- 스칼라도 키프레임 안에서는 배열: 불투명도 `"s": [100]`, 회전 `"s": [45]`.
- **이징 `cubic-bezier(x1, y1, x2, y2)`는 구간을 시작하는 키프레임 하나에 둘 다 쓴다**: `o: {x:[x1], y:[y1]}`, `i: {x:[x2], y:[y2]}`. 중간 키프레임은 자기가 시작하는 다음 구간의 `o`와 `i`를 갖는다. 마지막 키프레임에는 `o`/`i`를 넣지 않는다. 한쪽만 있거나 다음 키프레임으로 나눠 쓰면 BLOCK.
- 핸들 `x`는 0~1. `y`는 넘을 수 있다(넘침). 다차원 값은 `x`/`y`를 차원 수만큼 줘도 된다.
- 멈춤(계단): `"h": 1`. 숫자 카운트·타자기·깜빡임.

## 렌더러 제약

가장 중요한 절이다. Skottie(미리보기·렌더)와 lottie-web 5.x SVG(개발자의 웹 플레이어)는 지원 범위가 다르다. 미리보기에서 멀쩡한 것이 조용히 깨진 채 배포된다. `lottie.mjs check`가 정적으로 잡고, `--parity`가 실제로 그려 비교한다.

### BLOCK — 반드시 없앤다 (`check`가 exit 1)

| 걸리는 것 | 왜 | 대신 |
|---|---|---|
| `ty:"mm"` 머지 패스 | lottie-web SVG가 무시 → 합치기 전 패스가 겹쳐 나온다 | 하나의 `sh`로 미리 합친다. 구멍은 같은 그룹에서 `fl.r: 2`(evenodd) |
| 문자열 `x` (표현식) | Skottie는 평가 안 함, lottie-web은 함 → 두 화면이 갈린다 | 결과를 키프레임으로 굽는다. 반복 회전 = 선형 키프레임 2개, 랜덤 = 실제 키 시퀀스. (숫자·배열 `x` — 이징 핸들, 분리 위치 — 는 정상) |
| 비어 있지 않은 `ef` (레이어 이펙트) | 렌더러마다 지원 집합이 다르다 | 셰이프로 다시 만든다: 그림자 = 오프셋 복제 레이어 + 어두운 단색 + 낮은 불투명도 · 글로우 = 뒤에 방사형 `gf` · 틴트 = `fl` 색 직접 · 블러 = 빼거나 미리 렌더한 이미지 |
| `ty:5` 네이티브 텍스트 | Skottie는 폰트 파일, lottie-web은 CSS `@font-face` → 자간·베이스라인·줄바꿈이 다르고, 폰트가 없으면 에러 없이 시스템 폰트 | `node tools/lottie.mjs text`로 아웃라인 셰이프 |
| 최상위 `v fr ip op w h layers` 누락, JSON 파싱 실패 | 로드 자체가 불안정 / 열리지 않는다 | 전부 채운다. 저장 후 `check` |
| 내보낼 크기 150KB 초과 | 앱 번들에 그대로 실린다 | 키프레임을 프레임마다 찍지 말고 이징으로. 레이어·정점 수를 줄인다. 이미지는 파일로 |
| 키프레임 이징 `o`/`i` 한쪽만 | lottie-web은 시작 키프레임에서 `o`·`i`를 같이 읽다가 `undefined.x`로 그 레이어를 통째로 안 그린다. Skottie는 넘어간다 | 위 [키프레임](#lottie-json-핵심) 규칙: 둘 다 시작 키프레임에, 마지막 키프레임엔 없음 |
| 마스크에 `x`(페더) 없음 | lottie-web이 `x.k`를 바로 읽다 예외 → 레이어가 사라진다 | 마스크마다 `"x": { "a": 0, "k": 0 }` |
| film.json 불일치(kind·dur·fps·크기·없는 슬롯·label = sid) | 앱·내보내기가 다른 값을 본다 | `node tools/lottie.mjs sync films/<이름>` 후 label을 한국어로 |

### WARN — 통과하지만 `--parity`와 스틸로 그 프레임을 꼭 본다

| 걸리는 것 | 왜 | 대신 |
|---|---|---|
| `ddd:1` 3D 레이어 | Skottie는 진짜 3D, lottie-web은 흉내 → 겹침 순서가 바뀐다 | 2D로 평탄화. 깊이는 스케일·불투명도로, 순서는 레이어 순서로 |
| `bm ≠ 0` 블렌드 모드 | lottie-web은 CSS `mix-blend-mode` → 합성 대상이 다르다 | 결과 색을 미리 정해 단일 셰이프로. 보통 알파 합성으로 다시 디자인 |
| `tt` 트랙 매트 | 루마 매트의 휘도 계산이 다르다 | 알파 매트로. 단순 사각·원 클리핑이면 매트·마스크 대신 `rc`/`el`의 `s`·`p` 키프레임 |
| `st`/`gs`의 `d` 대시 | lottie-web 대시 오프셋·시작점 이슈 | 대시 행진 = 트림 패스 하나. 정적 점선 = 짧은 선분 도형으로 굽기 |
| 한 그룹에 `tm` 2개 이상 | 적용 순서 해석이 다르다 | 그룹을 나눠 트림 하나씩. 두 구간이 필요하면 패스를 복제 |
| 마스크(`masksProperties`) — 마스크가 있으면 항상 뜬다 | lottie-web 마스크는 `i`/`o`를 절대좌표로 쓴다 → **두 엔진을 동시에 만족하는 값이 없다** | 마스크 대신 `rc`/`el` 크기·위치 키프레임. 곡선 마스크가 꼭 필요하면 parity로 확인 |
| 움직임 검사: 이징 곡선 끊김 | 시간축 도함수가 구간 **중간**에서 0 → 재생 중 값이 순간 튄다(스틸로 못 잡음) | 핸들을 [움직임](#움직임) 표의 검증된 값에서 고른다. `x1`·`x2`를 0과 1 끝에 동시에 붙이지 않는다 |

### 안전 목록 (두 렌더러가 같게 그린다)

셰이프 레이어와 `sh rc el sr fl st` · `gf`/`gs`(대시 없이) · 리피터 `rp` · 프리컴프 · 타임 리맵 · 이미지 에셋(파일) · 그룹당 트림 하나 · 마스크(`x` 있음, 원시 도형 위주). 여기에 표현식·이펙트·머지 패스를 섞지 않으면 대부분의 앱 애니메이션을 만들 수 있다.

### 그 밖의 렌더 위험

- 블러·블룸·글래스·크롬·디더·진짜 3D·디스플레이스먼트는 Lottie로 같게 안 나온다. 벡터 도형·톤 단계로 흉내 내거나 뺀다.
- 모션 블러 대신 오프셋 복제 레이어(낮은 불투명도)로 속도감.
- 패스 모핑은 두 패스의 정점 수·방향이 같을 때만. 아니면 마스크·교체·크로스페이드.
- 리피터 사본은 각자 다르게 움직일 수 없다(오프셋만). 개별 움직임이 필요하면 레이어로 나눈다.
- 카운터·궤도·파티클·노이즈 같은 계산은 키프레임으로 굽는다(시드 고정: 같은 결과가 나와야 한다).

## 글자

네이티브 텍스트(`ty:5`)는 BLOCK이다. 글자는 아웃라인 셰이프로 만든다.

```bash
node tools/lottie.mjs text "문구" --font Pretendard-Bold --size 72 [--color #111111] [--slot ink] [--align left|center|right] [--tracking 0] [--name 이름]
```

- 출력(JSON 한 줄): `{ note, width, ascent, descent, layer }`. `layer`는 셰이프 레이어(`ty:4`). 글자마다 그룹 하나(`nm` = 글자), 그룹 `tr`의 기준점이 글자 중심이라 글자별로 스케일·회전·위치를 엇갈려 줄 수 있다. 칠 하나가 모든 글자에 적용되고, `--slot`을 주면 그 칠이 슬롯을 참조한다(슬롯 정의는 `slots`에 직접 넣는다).
- 레이어 위치(`ks.p`) = 정렬 기준점의 **기준선**. `--align center`면 기준선 가운데. `ip`/`op`(기본 99999)를 장면에 맞게 고치고 `ind`를 붙인다.
- 글꼴: `Pretendard-Bold` · `Pretendard-SemiBold` · `Geist-Bold` · `Geist-SemiBold`만. 디스플레이 서체 1개, UI 서체 1개.
- 세로 가운데: 아웃라인에는 줄 높이·자동 정렬이 없다. 대문자 높이 ≈ `0.7 × size`(소문자만이면 x높이 ≈ `0.52 × size`)로 잡고 `기준선 y = 상자 중심 y + 대문자 높이 / 2`. 한글은 스틸로 확대해 광학 중심을 확인한다. 크기가 다른 두 글줄이 한 줄에 있으면(라벨과 값) 같은 기준선이 아니라 각자의 대문자 높이 중심을 맞춘다 — 같은 기준선이면 작은 쪽이 가라앉아 보인다.
- 쌓인 글 덩어리 간격은 글자 크기에 비례: 제목과 바로 아래 줄 사이 ≈ 제목 대문자 높이의 0.5~0.8. 형제 덩어리끼리는 같은 간격 한 가지.
- 숫자 카운트: 자릿수마다 `h:1` 멈춤 키프레임으로 바꾸거나(글자 그룹 여러 벌 + 불투명도 계단), 고정폭처럼 보이게 자리마다 같은 폭 칸에 가운데 정렬. 자릿수가 흔들리면 안 된다.
- 문구가 바뀌면 다시 `text`를 돌려 레이어를 교체한다(글자 그룹 수가 바뀌니 엇갈림 키프레임도 다시).

## SVG 에셋

디자이너가 **그대로 쓰기**로 첨부한 SVG(`refs/`)는 눈대중으로 다시 그리지 않는다. 패스를 셰이프 레이어로 옮긴다.

- 먼저 본다: `viewBox`, width/height, 그룹, transform, `fill-rule`, 마스크·clipPath, 그라데이션, `<style>`·class, `<text>`, filter.
- viewBox를 지킨다: viewBox 좌표를 그대로 `sh` 정점으로 쓰고, 레이어 `ks`의 위치·스케일로 컴포지션에 맞춘다. 마지막 정지 프레임이 원본 SVG와 같은 비율·위치·간격이어야 한다(로고 락업은 절대 바꾸지 않는다).
- SVG 패스 → `sh`: 절대좌표로 풀고, 베지어 제어점은 정점 기준 **상대좌표**로 `i`(들어오는)·`o`(나가는)에 넣는다. 2차 곡선은 3차로 올린다(제어점 = 끝점 + 2/3 × (q − 끝점)). 중첩 transform은 정점에 미리 곱해 둔다.
- 칠 규칙: `fill-rule="evenodd"`면 `fl.r: 2`, 아니면 `1`. 구멍(도넛, 글자 속)은 같은 그룹 안 여러 `sh` + 한 `fl`로 — 머지 패스(`mm`)는 BLOCK. 겹친 하위 패스로 면을 지우는 모양이면 단순한 도형 스택으로 다시 나눈다.
- 스타일: CSS class·`<style>`·상속 색을 각 도형의 `fl`/`st` 값으로 풀어 쓴다. 색은 브랜드 색이면 슬롯으로.
- 선: 트림 그리기가 애니메이션 자체면 `st`로 두고 `lc`·`lj`를 원본대로. 아니면 선을 칠로 확장한 SVG를 디자이너에게 받는 편이 안전하다.
- `<text>`는 그리지 않는다 — 아웃라인으로 바꾼 SVG를 받거나 `lottie.mjs text`로 만든다. filter·blur·blend는 뺀다(렌더러 제약). clipPath·mask는 `rc`/`el` 키프레임으로 대체할 수 있는지 먼저 본다.
- 움직일 단위는 의미 있는 부분(마크/워드마크/액센트, 아이콘의 의미 부분)으로 그룹을 나누고 `nm`을 붙인다. 임의 패스 조각을 따로 움직이지 않는다.
- 확인: 정지 프레임을 원본과 같은 크기로 비교. 구멍이 메워짐, 선 잘림, 그라데이션 튐, 교차 영역 차이를 본다(`--stills`, `--parity`).
- 자세한 절차: `prompts/lottie-recipes/svg-animation.md`.

## 움직임

Lottie에는 스프링이 없다. 모든 움직임은 베지어 이징 키프레임이다. 영상 필름의 스프링 프리셋을 이렇게 옮긴다(60fps 프레임).

| 영상의 `sp()` | 쓰는 곳 | 베지어 `x1,y1,x2,y2` | 길이 |
|---|---|---|---|
| `snappy` | 버튼 눌림, 토글, 인디케이터 | `.20,.75,.34,.94` (entrance-sharp) | 8~18f |
| `ui` (기본) | 컨테이너·카드·상태 이동 | `.65,0,.35,1` (travel-balanced) 이동 · `.00,.65,.51,.99` (settle-soft) 착지 | 18~30f |
| `camera` | 큰 레이아웃 이동, 팬·줌 | `.65,0,.35,1` | 36~60f |
| `heavy` | 큰 타이포, 로고 락업 | `.00,.65,.51,.99` | 40~60f |
| `playful` | 마스코트, 스티커 (**UI 금지**) | `.94,.75,.34,.94` + 넘침 키프레임 | 24~40f |

그 밖의 검증된 곡선:

| 이름 | 행동 | 베지어 |
|---|---|---|
| `exit-accelerate` | 퇴장, 하드컷 짝 | `1.00,.02,.54,.42` |
| `travel-cut` | 끊기는 이동(컷·마스크로 끝나는 것만) | `.15,.85,.95,.05` |
| `kinetic-ui` | 표정 있는 작은 상태 변화(모든 UI 아님) | `.85,.46,.14,.53` |
| 선형 `0,0,1,1` | 회전 로더, 스캐너, 진행 루프 | — |

- 표에서 가장 가까운 것을 골라 한 가지 성질(가속, 활공, 착지 부드러움, 퇴장 속도)만 조정한다. 새 곡선은 맞는 게 없을 때만. 바꾼 뒤 `check`의 움직임 검사를 통과해야 한다.
- **넘침**: UI에서는 쓰지 않는다(CLAUDE.md: 통통 튀는 이징 금지). 브랜드·캐릭터에서만, 작게. 목표를 4~8% 지나는 키프레임 하나 + 6~10f 뒤 되돌아오는 키프레임이 기본(두 렌더러에서 안전). 짧게 쓰려면 끝 `i.y`를 1.08~1.2.
- **예비 동작**: 빠른 리빌 전 반대쪽으로 살짝(3~6f, 2~4%). 시작 `o.y`를 0 아래로.
- 모든 속성에 같은 이징·같은 프레임을 주지 않는다. UI·패널·기계적 상태는 **잠금**(같이 시작·같이 끝), 로고·히어로는 **앞섬/따름**(한 속성이 2~6f 앞서고 다른 속성이 따라옴), 가독성이 중요하면 **불투명도 먼저**(불투명도는 6~10f에 끝, 위치·스케일은 계속 착지).
- 계층: 초점 요소만 가장 강한 성격(넘침, 스냅). 보조 요소는 조용한 곡선.
- 거리·길이: 큰 이동은 더 부드럽게·더 길게. 작은 UI는 짧게. 카메라(전체를 움직이는 널)는 그 안의 물체보다 차분하게.
- 엇갈림(stagger): 작은 UI 2~6f, 표현적 장면 4~14f. 의미 있는 시작점(첫째·가운데·경로 방향·초점)에서.
- 리빌 문법: 생성 → 착지 → **멈춤**(메시지가 읽히는 곳). 읽는 순서·중요도 순으로. 한 비트에 큰 장식 하나.
- 전부 페이드인 금지(CLAUDE.md). 마스크 와이프 대신 `rc` 크기 키프레임, 트림 그리기, 스케일 착지, 의도한 컷을 쓴다.
- 데드 타임 금지: 한 번 재생 에셋은 마지막 포즈에서 멈추는 것이 "멈춤 비트"다(10~20f면 충분). 그보다 길게 비우지 않는다. 여러 장면이면 2~4초마다 새로운 일.
- **루프**: 마지막 프레임 = 첫 프레임(위치·색·불투명도·**속도**). `op` 제외이므로 값이 프레임 `op`에서 처음 값으로 돌아오게 키프레임을 `t = op`에 둔다. 회전은 360°의 정수배, 파동은 정수 주기, 반복 요소는 위상 오프셋(인덱스·거리·경로 위치 기준)으로 — 모두 같은 박자로 맥박치면 기계적으로 보인다. 이음새에서 속도가 맞도록 처음·끝 구간의 핸들을 대칭으로(또는 선형).
- 템포: 브리프에 곡·BPM이 있으면 `film.json`의 `bpm`·`beatOffset`에 적고 큰 동작을 비트 프레임(`fr × 60 / bpm`f 간격 — 60fps·120BPM이면 30f)에 맞춘다. 앱 UI 에셋은 보통 리듬보다 반응성이 우선이다.

## 룩

CLAUDE.md의 룩 규칙 위에, 앱·웹 에셋에서 특히:

- **프리미엄 = 빼기.** "깔끔·미니멀·모던·고급"이라는 말은 덜어 내라는 신호다. 고급스러움은 크기·굵기·밝기·여백·타이밍이 만든다. 카드·테두리·구분선·그림자·글로우·겹친 틴트가 아니다.
- **크롬 예산 0.** 감싸는 카드·컨테이너·테두리·구분선은 여백과 정렬로 할 수 없는 일을 할 때만. 분리는 여백·정렬 → 헤어라인 하나 → 칠/테두리 카드 순으로. 지웠을 때 의미가 사라지지 않으면 지운다.
- **표면 톤 하나.** 거의 검정 두 개, 거의 흰색 두 개를 겹쳐 "표면"을 흉내 내지 않는다(탁해 보인다). 카드 표면이 꼭 달라야 하면 목적이 분명한 한 단계만.
- **구분선 하나의 굵기·하나의 색.** 제목 밑줄과 열 구분선이 다르면 안 된다.
- **색:** 브랜드 색이 있으면 그것부터. 없으면 순수 흑백 대비 + 포인트 1개. 역할(배경/초점/포인트/상태)을 먼저 정하고 색을 더한다. 채도는 한 요소에 가둔다. 깊이는 톤 단계·헤어라인으로 먼저.
- **오브젝트 예산:** 초점 1 · 보조 1 · 포인트 체계 1에서 시작. 디테일은 이해·계층·상태·브랜드·읽기 리듬에 기여할 때만. 빈 둥근 카드, 장식 원, 장식 그리드 배경은 의미 있는 것(아이콘, 상태 점, 숫자, 라벨)으로 바꾸거나 지운다.
- **마지막 정지 프레임이 디자인이다.** 한 번 재생 에셋은 마지막 포즈가 앱에 남는 화면이다. 첫 프레임·마지막 프레임을 각각 완성된 정지 디자인으로 짠다. 움직임은 그 구도를 드러낼 뿐, 약한 구도를 구하지 못한다.
- **투명 에셋 프레이밍:** 아트를 쓸 만큼 꽉 차게, 그러나 넘침·스케일 여유는 남긴다(어떤 프레임에서도 캔버스 가장자리에 잘리지 않게). 시각 중심(둥근 도형·비대칭 로고)으로 광학 보정.
- **투명이면 배경 픽셀 0.** 미리보기 대비가 필요해도 배경 레이어를 굽지 않는다. 칠한 배경이면 맨 아래 전체 크기 `rc` + `bg` 색 슬롯, `film.json` `transparent: false`.
- 작은 크기에서도 읽혀야 한다: 아이콘·로더는 실제 들어갈 크기(예: 24~48px)로 줄여 봐도 형태가 알아보여야 한다. 얇은 선·작은 디테일을 줄인다.

## 검사와 완료 조건

순서대로 모두 통과해야 끝이다. "미리보기에서 괜찮다"는 완료가 아니다 — 미리보기는 배포되는 렌더러가 아니다.

1. `node tools/lottie.mjs check films/<이름>` — 호환(lottie-web) · 움직임(이징 끊김) · film.json 동기 · 내보낼 크기 150KB. **BLOCK 0.** WARN은 하나씩 해당 프레임을 3·4에서 본다.
2. `node tools/render.mjs films/<이름> --parity` — Skottie와 lottie-web 5 SVG로 같은 프레임을 그려 비교. 프레임마다 차이 **2% 미만**이면 통과. 실패하면 `out/<이름>/<WxH>/parity/parity.png`를 열어 어느 레이어가 다른지 보고, 원인이 WARN 항목이면 위 표의 대안으로 바꾼다. 경계선 안티앨리어싱 차이는 0이 되지 않는 게 정상이다.
3. 스틸: `node tools/render.mjs films/<이름> --stills 0.2,0.5,1`(핵심 시각) 또는 `--stills beats`(컨택트 시트). 최소 프레임 0 · 첫 의미 있는 비트 · 중간 · 착지 직후 · 마지막(`op - 1`) · 루프면 이음새 · 의미 비트(체크가 완성됨, 숫자가 멈춤, 로고가 맞춰짐).
4. 결정성: `node tools/determinism.mjs films/<이름>` (전달 전 한 번).
5. 배경 정책: 투명 에셋이면 정말 투명한지, 칠한 배경이면 `bg` 슬롯이 있는지.

**크리틱 채점** (`prompts/critique-pass.md`의 7항목을 Lottie에 맞게 읽는다)

| 항목 | Lottie에서 |
|---|---|
| 훅 | 처음 0.3초 안에 무엇이 일어나는지 보이는가(에셋), 첫 2초(여러 장면) |
| 폰 가독성 | 실제 들어갈 크기로 줄여도 형태·글자가 읽히는가 |
| 모션 품질 | 이징이 목적에 맞는가, 착지가 깨끗한가, 미끄러짐·튐·데드 프레임이 없는가 |
| 다양성 | 여러 장면이면 2~4초마다 새 일. 에셋 하나면 "한 가지를 분명히" 하는가로 본다 |
| 구도 | 여백, 정렬, 광학 중심, 마지막 정지 프레임의 완성도 |
| 브랜드 정확도 | 색·서체·원본 SVG 락업과의 일치 |
| 리듬 | 엇갈림 간격과 비트(곡이 있으면 비트 그리드) |

점수와 가장 큰 문제 3개(프레임/시각과 함께), 고친 점을 `review_log.md`에 남긴다. 루프 이음새와 parity 결과도 한 줄씩.
