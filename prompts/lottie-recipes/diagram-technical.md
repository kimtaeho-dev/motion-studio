# 레시피: 다이어그램 · 기술 애니메이션

흐름 따라 그리기, 선 애니메이션, 콜아웃, 구조 설명 그래픽, 단계 설명, 연결 리빌. 원본이 SVG면 `svg-animation.md`도. 공통 규칙은 `prompts/lottie.md`.

## 기본

- 장식보다 명료함. 시스템을 설명하는 가장 적은 노드·선·라벨·포인트에서 시작.
- 보는 사람이 이해해야 하는 순서대로 드러낸다.
- "기술적" = 어두운 그리드 + 파란 화살표 + 빈 둥근 카드 + 장식 원이 아니다. 구체적인 시각 체계를 고른다.
- 오버레이·에셋은 투명, 화면 전체 설명이면 `bg` 슬롯.

## 만들기 전에 정한다

- 마지막 프레임의 위상: 주 경로, 보조 묶음, 콜아웃 자리, 가장 강한 정지 읽힘.
- 시각 체계: 에디토리얼 라이트, 제품 UI, 미니멀 도식, 브랜드 시스템 맵 중 하나.
- 구조 관계: 순서는 체인, 부분-전체는 브래킷, 수렴은 궤도, 시스템은 방사, 비교는 그리드, 증거는 헤어라인 행.
- 노드마다 역할·상태·순서·지표·UI 조각·아이콘·라벨 중 무엇을 전하는지.
- 선이 뜻하는 것: 데이터 흐름, 의존, 순서, 소유, 상태 전이.

## 프리셋

| 이름 | 무엇 |
|---|---|
| `flow-trace` | 경로 순서로 선이 그려지고, 연결된 뒤 노드가 켜짐 |
| `callout-pop` | 대상이 보인 뒤 라벨·배지 등장 |
| `scan-highlight` | 하이라이트가 경로·구간을 따라 이동(짧은 트림 구간의 `o` 이동) |
| `node-network` | 노드가 묶음으로, 연결이 뒤따름 |
| `step-build` | 논리 단계 하나씩 쌓음 |
| `orbit-system` | 방사 노드가 그려지고 은은히 돌며, 라벨은 반대로 돌려 똑바로 유지 |

## 타이밍과 이징 (60fps)

- 단순 다이어그램: 75~150f. 여러 단계: 150~300f(여러 장면이면 숏리스트 게이트).
- 선 트림은 선형 또는 거의 선형, 노드·라벨은 `.00,.65,.51,.99` 착지.
- 큰 단계마다 이해할 만큼 멈춘다.

## 만들기

- 경로, 노드, 라벨, 하이라이트를 레이어로 나누고 `nm`을 붙인다.
- 선은 트림 패스(그룹당 하나), 노드는 작은 불투명도·스케일 착지. 점선은 WARN — 실선 + 트림, 또는 짧은 선분 도형으로 굽기.
- 패스 모핑 금지. 기술 다이어그램은 도형이 안정적이어야 한다.
- 노드에 쓸모 있는 내부 디테일: 아이콘, 숫자, 짧은 라벨(`lottie.mjs text`), 상태 점, 포트.
- 화살표는 방향이 모호할 때만. 주·보조 흐름은 선 굵기·불투명도로 구분.
- 그리드는 정렬 구조·축으로만, 장식 배경으로 쓰지 않는다. 떠 있는 원은 포트·상태 표시·배지로 바꾸거나 지운다.
- 궤도 시스템은 부모 널이 돌면 라벨에 반대 회전을 준다.
- 붐비면 디테일을 더하기 전에 노드를 줄이거나 라벨을 합치거나 주 경로를 강조한다.

## 흔한 실패

- 전부 한꺼번에 나와 설명이 사라진다. 선이 흐름 반대로 그려진다.
- 라벨이 겹치거나 대상보다 먼저 나온다.
- 빈 둥근 사각형으로 자리표시처럼 보인다. 흔한 노드 메시가 관계를 설명하지 않는다.
- 가짜 복잡도가 소음만 더한다.

## 통과 조건

- 드러나는 순서가 시스템을 설명한다.
- 마지막 프레임이 깨끗하고 정확한 다이어그램이며, 노드가 애니메이션 없이도 의미 있다.
- 선·화살표·라벨이 읽히고, 의도한 여백으로 균형 잡혀 있다.
